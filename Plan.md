# План автоматизации

**Объект:** учебное приложение покупки тура. Проверяются два способа оплаты, ответы банковского симулятора и фиксация результатов в MySQL и PostgreSQL.

| Сценарии | Проверки |
|---|---|
| Дебетовая карта: одобрение и отказ | Результат в интерфейсе; `payment_entity` хранит статус и сумму; `order_entity` ссылается на платёж |
| Кредит: одобрение и отказ | Результат в интерфейсе; `credit_request_entity` хранит статус; заказ ссылается на заявку |
| Две конфигурации СУБД | Все сценарии выполняются с MySQL и PostgreSQL; реквизиты карты не сохраняются |

**Инструменты:** Java 11 и Gradle Wrapper для запуска; JUnit 5 для сценариев; Selenide для браузера; Allure для пошагового отчёта и скриншотов; JDBC для чтения обеих БД; Docker Compose для окружения; банковский симулятор из задания для стабильных ответов.

**Возможные проблемы:** приложение содержит дефекты и тесты могут падать; медленный запуск БД или симулятора; различия SQL-диалектов; в БД остаются записи прошлого запуска. Снижение риска: healthcheck контейнеров, ожидание появления новых записей, запросы только на чтение и отдельный запуск двух профилей.

**Оценка:** изучение приложения и модели данных — 2–3 ч; тест-дизайн — 2–3 ч; реализация UI/JDBC и Allure — 5–7 ч; настройка среды и проверка СУБД — 3–5 ч; отчётность и исправления — 2–3 ч. Итого 14–21 ч с учётом рисков.

**Сроки:** день 1 — сценарии и инфраструктура; день 2 — UI-тесты, запросы к БД и отчёт; день 3 — прогоны на обеих СУБД, регистрация дефектов и итоговые документы.
